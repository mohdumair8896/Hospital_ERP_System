# Design Inspiration Sources: Inspo MCP and Refero

Status: complete

Research date: 2026-10-24. Read-only research for D:\Hospital Project (apps/website, apps/erp).
Conventions: "Observed" = seen directly on the page/repo. "Inferred" = my interpretation, marked as such.

## 1. Inspo (inspomcp.dev and github.com/Nutlope/inspo)

### 1.1 What it is and how it works
- Inspo is a curated, free archive of real production **marketing websites**: 832 sites, 2,320 captured pages (desktop + mobile), 68 reference components and a DESIGN.md per site. It is browsable at inspomcp.dev and queryable by coding agents over MCP. It is owned and operated by Together AI, and the credits read "Youssef & Hassan". (Logs A, C, K)
- End to end (observed in the README and repo, with the flow inferred from file names; Logs D, E, H):
  1. Curators list URLs in `apps/worker/src/seed-urls.ts` (and txt queues), and contributors can add more by PR.
  2. A Playwright worker (Docker, Fly.io) captures desktop and mobile screenshots, removes cookie and modal overlays, and extracts palettes, type ramps, CSS variables, fonts, the tech stack and component crops.
  3. Together AI models tag each capture (style, industry, vibe, macrostructure) and write an "autopsy" (fold-by-fold breakdown) and a "northstar" summary. Together AI embeddings power semantic search and find_similar.
  4. A static catalogue (JSON + embedding binaries) is built and published to Vercel Blob. There is no database at query time.
  5. The catalogue is served two ways: the Next.js 16 / Tailwind v4 gallery, and the MCP server (stdio via `npx -y inspo-mcp`, or Streamable HTTP at https://inspomcp.dev/api/mcp). The hosted endpoint is free and unauthenticated, rate-limited, and read-only.
- Data source: live public websites chosen by the curators. Every screen credits and links its source, and takedowns go through /dmca.

### 1.2 Features, pages and components
- Site pages (Logs A, K, L, M, AH, AI, AJ):
  - **Home**: hero with the install command, gallery cards, "For coding agents".
  - **Archive** (/screens): search for styles, brands and fonts, or paste a URL; filter-chip popovers for Industry, Style, Mood, Color, Structure, Mode and Mobile pairs; 14 pages of 60 (inferred from the counts).
  - **Site** (/sites/<slug>) and **screen** (/screens/<slug>) detail pages: captures; palette with hex + OKLCH + role, click-to-copy and find-by-colour; type ramp table; radius; container; exports as CSS vars, Tailwind v4 config or DESIGN.md; a copyable agent prompt; similar sites.
  - **Examples**: 30 agent-built demo sites, each with a score.
  - **Components**: 10 categories, rendered live, plus real-site crops.
  - **Collections**: 3 editorial issues.
  - **MCP**: tools, a browser playground for search_screens, the macrostructure explainer.
  - **About** (self-host), **Takedowns**, **Colophon**.
  - Routes for /compare and /extract exist in the repo; they were not opened.
  - A Cmd+K palette with grouped results and key hints (Cmd+C copies DESIGN.md, Cmd+S saves), and a light/dark toggle.
- MCP: 15 tools (9 in a "lite" profile): recommend, search_screens, find_similar, find_by_color, find_examples_for_macrostructure, get_screen, get_design_system, compare, find_components, find_reference_components, get_reference_jsx, get_site_pages, list_collections, get_collection, get_filters. Token budgeting (maxTokens; images=none). (Logs C, F, G)
- Taxonomy: 9 page types (landing, pricing, features, auth, about, blog, changelog, docs, other), 19 macrostructures, 17 crop component types, 10 reference types, and 24 industries (with "health" = Health & Fitness). **There are no app or dashboard page types, and no table, form, sidebar, command-palette or calendar components.** (Logs G, H)
- Health coverage: 25 Health & Fitness entries. Most are wellness and fitness; a few are clinics or diagnostics (hx-clinic, functionhealth, instituteofhealth, alliahealth, modernhealth). There is no hospital. (Log AH)

### 1.4 Design principles, prompts and conventions
- Server instructions sent to the agent: use Inspo for new pages, redesigns or named aesthetics; **skip it when the project already has a design system; the project's conventions win**. Suggested budget: 1 recommend, 1-2 search_screens, then 3-5 get_screen calls. (Log G)
- HERO_GUIDANCE: the whole hero sits above the fold at about 1280x800 / 100svh, with the display type at 2-3 lines. SPACING_GUIDANCE: 80-160 px between sections (median 96 px across 671 sites), a centred column with at least 24 px mobile padding, container inline padding kept separate from section block padding. (Log G)
- DESIGN.md "Notes for the agent": keep type-ramp ratios rather than pixel values, verify colour roles, round spacing to a 4/8/16 scale, trust extracted CSS vars over inferred values. (Log J)
- Reference-component conventions: Tailwind + CSS-variable tokens (paper, ink, accent, accent-ink, muted, rule, plus bg/fg/border aliases); no props; reduced-motion-aware marquees; restraint (one loud CTA, honest logo labels, sourced stats, native <details> for FAQ). (Log I)

### 1.5 Recommendation (report only; nothing installed)
- **Website (apps/website): useful, moderately.** recommend, get_reference_jsx and DESIGN.md exports can speed up hero, FAQ, testimonial, stat, CTA, nav (mega menu, search-first) and footer (address card) variants. The hero-fit and 80-160 px spacing rules are cheap, objective checks for the homepage. Health references are wellness-skewed, so use them for tone, not for clinical IA.
- **ERP (apps/erp): low value.** The corpus has no dashboards, tables, forms or app shells, and the server itself tells agents to skip it when a design system exists (we have a shadcn-style one).
- If the user wants it, the lowest-risk path is **per-project, website-only, lite and text-only**: e.g. `claude mcp add --transport http inspo "https://inspomcp.dev/api/mcp?profile=lite&images=none&maxTokens=4000"` run inside apps/website. The parameters come from the README; this was **not run**. Avoid the auto-installer's global edits to every detected client, or run it with `--dry-run --client` first. Alternatively, skip the MCP and just use the site manually: copy DESIGN.md or Tailwind exports and read the live component pages.
- Privacy note: the hosted endpoint says it logs only the tool name, success and duration. Queries go to a third party (Together AI-operated), so don't put patient data in briefs.
- For ERP references, Refero is the stronger source (section 2), but its MCP, flows and full library need a paid Pro plan.

### 2.3 Per-category pattern catalog
Each pattern gives: Layout / Interaction and motion / Why it works / Build notes for our stack. Motion was **not observable** (static captures), so every motion line is a recommendation (inferred). Sources are the LOG entries below.

**Dashboards** (Runey, Asana, Stripe, Zendesk, Monarch, Clearful)
- P-DASH-1 KPI strip: Layout: 3-4 equal tiles (label, large value, delta pill, caption). Motion: number count-up of no more than 400 ms on first load only; no motion on refetch. Why: scannable at a glance and comparable in one row. Build: a `<KpiCard>` on our Card; tabular-nums; a delta Badge in success or destructive; `grid-cols-2 lg:grid-cols-4`.
- P-DASH-2 Hero chart + right rail: Layout: a 2/3-width line or area chart, with a 1/3 rail for an activity feed and quick actions. Motion: recharts' own animation, short; the rail list fades in. Why: one primary trend, with the "what changed" feed next to it. Build: the existing `charts/AreaChartInteractive.tsx`; rail = Card + ScrollArea (inferred: a Radix scroll-area would need adding).
- P-DASH-3 Global time-range + filter row: Layout: segmented range buttons or a dropdown in the header; a filter-dropdown row with "Currently viewing <range>" text. Motion: none. Why: every tile is scoped by one control and the scope is visible. Build: Radix Select or ToggleGroup; keep the state in the URL query.
- P-DASH-4 Per-widget states: Layout: each widget handles its own loaded, skeleton or empty state (Asana Home). Motion: skeleton shimmer, then a 150 ms crossfade. Why: there are no full-page spinners and partial data shows early. Build: the existing `ui/shimmer.tsx`; Suspense or isLoading per card.

**Data tables** (Wrike, Mangomint, Stripe, Cake Equity)
- P-TBL-1 View switcher + toolbar: Layout: tabs (Table / Board / Timeline) and quiet filter, sort and "Fields" chips above the grid. Motion: the tab underline slides (framer-motion layoutId). Why: one dataset, several lenses, with filters always in reach. Build: Radix Tabs + DropdownMenu checkbox items for column visibility (TanStack column visibility).
- P-TBL-2 Status pills + priority dots + overdue red: Layout: soft-tinted pill per status; a coloured dot + label for priority; dates in destructive when overdue. Why: colour carries state without extra columns. Build: a Badge `variant` map; never colour alone, always paired with text (a11y).
- P-TBL-3 Tree or group rows + inline add row: Layout: expandable parents with indented children; "+ Item" at the bottom. Motion: height animation on expand (AnimatePresence). Why: hierarchy without leaving the grid. Build: TanStack `getExpandedRowModel` / grouping.
- P-TBL-4 Report = parameter form over a ruled table: Layout: date range, group-by and sort selects plus a toggle, then Generate, with PDF/Excel export next to it; right-aligned numerics; a bold total row. Why: reproducible reports. Build: react-hook-form + zod (already deps) for the params; table `<tfoot>`.
- P-TBL-5 Audit-style rows: Layout: User (avatar, name, email in two lines) | Action pill (Added green / Updated amber) | plain-language description | Date over time. Why: humans read sentences, not JSON. Build: render a description template per event type; keep a "view raw" drawer for the integrity hash.

**Forms, settings and onboarding** (Wix, Asana, Attio, Lovable, Hers)
- P-FORM-1 Settings shell: Layout: a dedicated sidebar grouped by scope (Account / Workspace / Security & compliance, with Audit logs placed there); breadcrumb + title + one-line description; one bordered card per concern. Why: predictable placement, and the scope is obvious. Build: reuse `ui/sidebar.tsx` with group labels; a `<SettingsSection>` card.
- P-FORM-2 Read-then-edit fields: Layout: labels left of values, an edit pencil or "Edit password" outline button per field; a security to-do card on the right (verify email, enable 2FA). Why: avoids accidental edits of identity data. Build: a Dialog per sensitive edit; a side card listing incomplete compliance steps.
- P-FORM-3 One question per step: Layout: a chrome-less step, a large question, a "why we ask" line, a single control, Back/Next, and a "01 / 07" counter with a progress bar (Hers, Asana). Motion: a 150-200 ms slide or fade between steps; the progress bar width animates. Why: lowers cognitive load, and the reason line builds trust for sensitive questions. Build: matches our 5-step booking wizard; framer-motion AnimatePresence with `mode="wait"`; respect prefers-reduced-motion.
- P-FORM-4 Modal record form with keyboard hints: Layout: a breadcrumb in the modal header (Choose list > Add); Cancel (Esc) and a primary button (Cmd+Enter) that stays disabled until valid. Why: fast for power users, and it prevents invalid submits. Build: Radix Dialog + rhf/zod `formState.isValid`; kbd hint spans.

**Calendars and scheduling** (GlossGenius, Sunsama, Amie)
- P-CAL-1 Resource time grid: Layout: a Day/Week dropdown, a date stepper, a staff or resource filter, hatched unavailable time, and appointment blocks (time, patient, service, room). Interaction: click a block to open the side sheet; click empty space to create. Why: mirrors how front desks think (who, when, where). Build: no time-grid lib in deps; a CSS grid is feasible, or add a scheduler lib (decision needed). Hatching via `repeating-linear-gradient`.
- P-CAL-2 Appointment side sheet (not a modal): Layout: patient identity, contact, a service list with colour bars, duration, price, room, assigned clinician + status, a **Notes/Forms section mentioning SOAP notes**, and Edit / Checkout at the foot. Motion: slide in from the right (about 200 ms). Why: the calendar stays visible for context. Build: Radix Dialog styled as a sheet (the shadcn Sheet pattern; not in ui/ yet).
- P-CAL-3 Success toast after create: a bottom-centre toast with a check and close. Build: `sonner` is already a dependency (and ui/toast.tsx exists).
- P-CAL-4 Day columns (Sunsama): Layout: kanban columns per day, cards with time chips and tags, a progress bar per day. Why: a good fit for queue or rota views. Build: CSS grid columns; drag-and-drop optional (a dnd lib would be a new dependency).

**Login** (Cohere, Monday)
- P-AUTH-1 Centred card, no chrome: Layout: logo, title, SSO buttons, email + password with an eye toggle, an inline "Forgot password", terms microcopy, and a help link. Why: zero distraction, and recovery paths are right there. Build: our LoginScreen; add a password-visibility toggle and a help or IT-desk link (staff ERP).
- P-AUTH-2 Email-first: Layout: one email field + Next, with the password (or SSO redirect) on step 2. Why: lets the org route to SSO; less clutter. Build: optional for the ERP if SSO is planned (inferred).

**Search and command palettes** (Cycle, Zendesk, Inspo's own Cmd+K)
- P-CMD-1 Cmd+K palette: Layout: a centred modal, an input "Type a command or search", scope chips, grouped results (Actions, Recently visited, Navigation), a shortcut hint on each row, and a footer legend. Motion: about 120 ms scale and fade from 0.98; the list height animates. Why: one entry point for navigation, records and actions. Build: **cmdk is not in deps** (add it, or build on Radix Dialog + a roving listbox). Register commands per module (Reception: "Register patient", "Find MRN"...).
- P-CMD-2 Filter popover with search + Apply: Layout: a search box, Selected/Excluded tabs, checkbox list, Select all, Apply. Why: multi-select on long lists without page reloads. Build: Radix Popover (not in deps) + Checkbox; TanStack column filters.

**Empty and loading states** (Navan, Stripe, Asana, Attio, Monarch)
- P-EMPTY-1 Keep the frame, show zeros: axes, tabs and filters remain; the copy names the scope ("no bookings for this timeframe"). Why: no layout jump, and it tells users how to get data. Build: an `<EmptyState scope=...>` with an icon, one line and an optional action.
- P-EMPTY-2 First-run = setup checklist: an activation banner + get-started cards + a progress counter ("Help and first steps 2/9", "86%"). Why: turns blank into a guided task. Build: fits Staff Provisioning and Integration monitor first runs.
- P-LOAD-1 Shaped skeletons per widget, with "All clear!" empty notification states. Build: ui/shimmer.tsx; aria-busy on the container.

**Notifications and activity** (Cake Equity, Airtable, Monarch, Attio)
- P-NOTIF-1 Bell popover: a header with Clear all + Settings, a grouped list, and a friendly empty state. P-NOTIF-2 Toasts: short past-tense text, an icon, close, bottom-left or bottom-centre. P-NOTIF-3 Activity timeline: grouped by period, summarising multi-field edits with "show all changes". Build: sonner for toasts; Radix Popover for the bell (needs adding); the timeline as a list with relative time.

**Record header (patient-banner analogue)** (Attio person record)
- P-REC-1: Layout: a pager (1 of N in list), avatar + name + key chips, primary actions at right, tabs with counts (Activity, Notes, Tasks, Files), and a persistent right Details panel. Why: identity and context never scroll away. Build: a sticky `<PatientBanner>` (name, MRN, age/sex, allergies chip in destructive, attending clinician, encounter status) + Radix Tabs; right panel for vitals and meds. (Inferred mapping; Refero has no EHR examples.)

**Landing sections: hero, pricing, FAQ, testimonials** (type 44 trending, Wealthsimple, Headspace, Officevibe, Doctronic, Hers)
- P-LAND-1 Hero: one dominant visual, a 2-3 line headline, at most 2 CTAs, minimal nav, all above the fold (matches Inspo HERO_GUIDANCE). P-LAND-2 Section rhythm: alternate white, tinted and dark bands with large spacing. P-LAND-3 Pricing: radio-card plan selector with a "best value" badge and renewal fine print right under it (Headspace); for a hospital, health-check packages. P-LAND-4 FAQ: left title + right accordion, several items open at once, placed after the final CTA (Wealthsimple); for long FAQs, Inspo's search-led variant. P-LAND-5 Testimonial: one large pull quote with a photo and a source line, followed by a stat + CTA band (Officevibe). P-LAND-6 Health intake: chat-style symptom input as the hero with trust signals and escalation to a clinician (Doctronic); a modal stepper with a "why we ask" line (Hers). Build: Next.js sections; Radix Accordion is not in deps (native `<details>` works, as Inspo recommends); framer-motion whileInView fades of no more than 300 ms.
